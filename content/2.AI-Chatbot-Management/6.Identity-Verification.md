Authenticate users in your Verly AI widget just like they're authenticated on your website.

Identity verification allows you to securely authenticate your users in the Verly AI widget. When an end user is logged into your website, you can identify them to your AI Agent so the widget knows who they are and can provide personalized, authenticated experiences.

## When to Use Identity Verification

### Personalize the Chat Experience

Make your AI Agent recognize logged-in users so it can:

- Greet users by name instead of saying "Hello there"
- Show content relevant to their subscription or role
- Provide support based on their history with your service

### Enable Actions with User Data

When you configure custom actions that need user-specific data:

- Custom actions can automatically receive the user's ID, email, and other fields via template variables like `{{contact.externalId}}`
- Custom attributes like plan, company, or account IDs are available as `{{contact.metadata.<key>}}`
- No need for the AI to ask "What's your email?" — it already knows

### Sync Contacts Automatically

By sending user contact information in the JWT, Verly AI will automatically create or update the contact record. No separate API calls needed. Custom attributes sent in the JWT are persisted to the contact and available across sessions.

---

## Prerequisites

- A website with the Verly AI embed script already installed and working
- A backend server that can sign JWT tokens (Node.js, Python, PHP, Ruby, or any language with a JWT library)

---

## Get Your Secret Key

Navigate to your Verly AI Dashboard to get your verification secret:

1. Go to your **Verly AI Dashboard** and select your AI Agent
2. Navigate to **Deploy** > click the **Identity** tab
3. Click **Generate Secret** to create your verification secret
4. Copy the secret key (starts with `iv_`)

::prose-warning
**Important:** Store this secret securely in your backend environment variables. Never expose it in client-side JavaScript.
::

## Implementation Guide

### How It Works

With a JSON Web Token (JWT), you can securely pass a user's identity to Verly AI. This serves three purposes:

1. **Identifies the user** to the chatbot (cryptographically verified)
2. **Creates or updates** the user's contact record in Verly AI
3. **Enables user-aware actions** by making user data available as template variables

```
Your Backend          Your Frontend          Verly AI Widget          Verly AI Backend
────────────          ──────────────          ───────────────          ────────────────
User logs in
Sign JWT with
VERLY_SECRET ────────> Receives token
                       Calls verly(
                         "identify",
                         { token, name }
                       ) ──────────────────> Sends token with
                                             every message ──────────> Verifies JWT
                                                                       Resolves contact
                                                                       Persists custom_attributes
                                                                       Enriches AI context
                                                                       Enables user-aware actions
```

The secret never touches the browser. The JWT is generated on your server, passed to the browser as an opaque blob, and verified on the Verly AI backend.

### Step 1: Generate the JWT on Your Server

The JWT payload contains the user information you want to pass. The only required field is `user_id` (or `sub`). All other fields are optional.

::code-group

```javascript [Node.js]
const jwt = require("jsonwebtoken");

// Secret key from the Verly AI Dashboard (Deploy > Identity tab)
const secret = process.env.VERLY_SECRET;

const payload = {
    user_id: "user_12345",                    // Required: unique identifier for the user
    email: "john.doe@example.com",            // Optional: user's email address
    name: "John Doe",                         // Optional: user's full name
    phonenumber: "+15551234567",              // Optional: user's phone number
    custom_attributes: {                      // Optional: persisted to contact metadata
        plan: "premium",
        company_id: "comp_789",
        region: "us-east"
    },
    exp: Math.floor(Date.now() / 1000) + (60 * 60)  // Required: expiration (1 hour)
};

const token = jwt.sign(payload, secret, { algorithm: "HS256" });
```

```python [Python]
import jwt
import time
import os

# Secret key from the Verly AI Dashboard (Deploy > Identity tab)
secret = os.environ["VERLY_SECRET"]

    },
    "exp": int(time.time()) + (60 * 60)
}

```

### Step 2: Identify the User in Your Frontend

Once you have the signed JWT, pass it to the Verly AI widget using `window.verly("identify", ...)`.

#### Option A: Dynamic identify (recommended)

Call this after the user logs in or when you have their identity:

```javascript
// Get the signed JWT from your backend
const token = await fetchTokenFromYourBackend();

// Identify the user to Verly AI
window.verly("identify", {
    // The token contains private data (email, user_id, custom_attributes)
    // which is protected. It is NOT visible to the chatbot.
    token: token,

    // These public attributes ARE visible to the chatbot.
    // The AI can use them to greet the user, personalize responses, etc.
    name: user.firstName,
    plan: user.plan
});
```

#### Option B: Pre-load before widget loads

Set the identity before the Verly AI embed script loads:

```html
<script>
window.verlyUserConfig = {
    token: tokenFromYourBackend,
    name: user.firstName,
    plan: user.plan
};
</script>

<!-- Your normal Verly AI embed script -->
<script src="https://widget.verlyai.xyz/embed.js" data-chatbot-id="..."></script>
```

---

### Step 3: Reset on Logout

When a user logs out, call `resetUser` to clear their identity from the widget. This is important to prevent identity leakage when multiple users share the same browser.

```javascript
// When the user logs out
window.verly("resetUser");
```

::prose-warning
**Important:** Always call `resetUser` on logout. This clears the identity token AND the stored contact/conversation IDs from the browser, ensuring the next user gets a clean session.
::

## Privacy Model: What the AI Can and Cannot See

Verly AI separates data into two categories:

| Data | Visible to AI? | Used in Actions? | Persisted? |
|------|---------------|------------------|-----------|
| Public attributes (passed outside JWT) | Yes | No | No |
| JWT payload (email, user_id, name, phone) | Yes (in session context) | Yes, via `{{contact.*}}` | Yes, on contact record |
| JWT custom_attributes | Yes (in session context) | Yes, via `{{contact.metadata.*}}` | Yes, merged into contact metadata |

**Example:**

```javascript
window.verly("identify", {
    token: token,        // Contains email, user_id, custom_attributes
    name: "John",        // AI CAN see this and will greet "Hey John"
    plan: "premium"      // AI CAN see this and can say "As a premium user..."
});
```

The AI receives a user context block that includes identity fields and public metadata. Template variables in custom actions are filled in server-side from verified data — the AI cannot fabricate or modify these values.

## Template Variables in Custom Actions

When a user is verified, their identity data is automatically available as template variables in your custom action configurations. No extra setup needed.

### Available Variables

| Variable | Value | Source |
|----------|-------|--------|
| `{{contact.externalId}}` | The `user_id` from the JWT | JWT payload |
| `{{contact.email}}` | User's email | JWT payload |
| `{{contact.name}}` | User's name | JWT payload |
| `{{contact.phone}}` | User's phone number | JWT payload |
| `{{contact.id}}` | Internal Verly AI contact ID | Auto-generated |
| `{{contact.metadata.<key>}}` | Any key from `custom_attributes` | JWT → persisted to contact |

### Where Variables Work

Template variables are substituted in **all parts** of a custom action request:

- **URL and endpoint:** `https://api.yourapp.com/users/{{contact.externalId}}/orders`
- **Headers:** `X-User-Email: {{contact.email}}`
- **Query parameters:** `?company={{contact.metadata.company_id}}`
- **Request body:** `{"customer_id": "{{contact.externalId}}", "plan": "{{contact.metadata.plan}}"}`

### Example Custom Action

If you configure a custom action with the endpoint:

```
GET https://api.yourapp.com/companies/{{contact.metadata.company_id}}/users/{{contact.externalId}}/orders
```

And headers:

```
X-User-Email: {{contact.email}}
```

When a verified user asks "Show me my orders", the AI triggers this action and Verly AI automatically fills in:

```
GET https://api.yourapp.com/companies/comp_789/users/user_12345/orders
X-User-Email: john.doe@example.com
```

The AI doesn't need to know the user's ID or company — they're injected by the system from the verified JWT.

### Missing Variables

If a template variable references a field that doesn't exist (e.g., `{{contact.metadata.nonexistent}}`), it resolves to an empty string. Your API should handle empty values gracefully.

## JWT Payload Reference

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `user_id` | string | Yes | Unique identifier for the user. Maps to `external_id` on the contact record. You can also use `sub` instead of `user_id`. |
| `email` | string | No | User's email address |
| `name` | string | No | User's full name |
| `phonenumber` | string | No | User's phone number |
| `custom_attributes` | object | No | Key-value data persisted to the contact's metadata. Available as `{{contact.metadata.<key>}}` in actions. Max payload size: 4KB. |
| `exp` | number | Yes | Token expiration time (Unix timestamp). Recommended: 1 hour. Maximum: 24 hours. |

> `user_id` should be a stable, unique identifier (like a database ID or UUID). Avoid using emails or usernames that might change. It must be a **string** — numeric IDs will be converted automatically, but strings are preferred.

## Security Best Practices

### Server-Side JWT Generation

Always generate JWTs on your server, never in client-side JavaScript:

- **Secure:** Generate JWT in your backend API
- **Secure:** Store the Verly AI secret in environment variables
- **Insecure:** Generate JWT in browser JavaScript
- **Insecure:** Include the secret key in client-side code

### Token Expiration

Always set an expiration time:

- **Recommended:** 1 hour (`exp: now + 3600`)
- **Maximum:** 24 hours
- **Never:** No expiration (security risk)

If a token expires mid-conversation, the chatbot silently degrades to anonymous mode. Re-call `identify()` with a fresh token to re-authenticate.

### Secret Rotation

When you rotate your secret in the Dashboard:

- All existing JWTs immediately become invalid
- Users will need to re-authenticate (get a new token from your backend)
- Use this if you suspect your secret has been compromised

### Tamper-Proof by Design

JWTs are cryptographically signed. If anyone modifies the payload (e.g., changes the `user_id` to impersonate another user), the signature breaks and Verly AI rejects the token. The browser cannot forge identities.

### Custom Attributes Size Limit

The `custom_attributes` payload is limited to **4KB** when serialized to JSON. Payloads exceeding this limit are silently dropped — other identity fields (user_id, email, name) are still processed normally.

The same 4KB limit applies to public metadata passed in the `identify()` call.

## How Contact Updates Work

When a user is identified via JWT, Verly AI automatically creates or updates their contact record:

- **New user (first time):** A new contact is created with `role='user'` and the JWT data
- **Returning user:** The existing contact is found by `user_id` and updated with any changed fields
- **Anonymous visitor who later signs up:** The visitor's existing contact record is upgraded to `role='user'` and linked to their `user_id`

### Custom Attributes Persistence

Custom attributes from the JWT's `custom_attributes` field are **persisted** to the contact's metadata using a shallow merge:

```
First request:   custom_attributes: { plan: "free" }
                 → Contact metadata: { plan: "free" }

Second request:  custom_attributes: { plan: "premium", region: "US" }
                 → Contact metadata: { plan: "premium", region: "US" }

Third request:   custom_attributes: {}  (empty or omitted)
                 → Contact metadata: { plan: "premium", region: "US" }  (unchanged)
```

- New keys are added
- Existing keys are overwritten with the new value
- Keys not in the new JWT are preserved
- Empty or omitted `custom_attributes` leaves existing metadata untouched

## Edge Cases

### Multiple Users on the Same Browser

If User A logs out and User B logs in on the same browser:

1. **If `resetUser` is called on logout:** User B gets a clean session.
2. **If `resetUser` is NOT called:** The system detects the contact belongs to a different `user_id`, refuses to merge contacts, and creates a new one for User B. No data leaks between users, but old conversation history may be visible until `resetUser` clears localStorage.

**Always call `resetUser` on logout.**

### Token Expires Mid-Conversation

- The chatbot silently degrades to anonymous mode
- Custom actions lose access to `{{contact.*}}` variables (they resolve to empty strings)
- No error is shown to the user
- Call `identify()` again with a fresh token to restore identity

### Invalid or Malformed JWT

Silently treated as anonymous — no error shown. The conversation works normally, just without personalization or user-aware actions.

### First Message Before Identify

If the user sends a message before `identify()` is called, a visitor contact is created. When `identify()` is later called, this visitor contact is **upgraded** with the JWT data. The conversation history is preserved.

### custom_attributes with Non-String Values

Template variables convert all values to strings:

```javascript
custom_attributes: {
    plan: "premium",         // → "premium"
    seats: 5,                // → "5"
    active: true             // → "true"
}
```

Nested objects within `custom_attributes` are **replaced entirely** on update (shallow merge, not deep merge). If you need to preserve nested fields, flatten them:

```javascript
custom_attributes: { config_theme: "dark", config_lang: "en" }
```

## Troubleshooting

### Identity Not Recognized

**Symptoms:** AI doesn't greet the user by name, custom actions don't have user context

**Check:**
- Verify the secret key in your Dashboard matches the one used to sign the JWT
- Ensure `user_id` (or `sub`) is present in the JWT payload
- Confirm the JWT hasn't expired (check `exp` claim)
- Make sure **Identity Verification** is enabled in the Dashboard (Deploy > Identity tab)
- Ensure `user_id` is a **string**, not a number

### Contact Data Not Available to Actions

**Symptoms:** Template variables like `{{contact.externalId}}` resolve to empty

**Check:**
- Verify the JWT was sent (check browser Network tab for `x-verly-identity-token` header)
- Confirm the JWT is valid (use the Token Tester in Dashboard > Deploy > Identity tab)
- Ensure the custom action endpoint uses the correct template variable syntax
- Remember: `{{contact.metadata.plan}}` requires `plan` to be in `custom_attributes`, not a top-level JWT field

### Custom Attributes Not Persisting

**Symptoms:** `{{contact.metadata.*}}` variables resolve to empty despite being in the JWT

**Check:**
- Ensure `custom_attributes` is a flat object (not nested within another field)
- Verify the serialized size is under 4KB
- Check that the key names are correct (case-sensitive)
- Note: changes are visible on the **next** request after the JWT is processed

### Multiple Users on Same Browser

**Symptoms:** User B sees User A's conversations or data

**Solution:** Always call `window.verly("resetUser")` when a user logs out.

## Complete Implementation Example

### 1. Backend: Generate JWT on Login

```javascript
const jwt = require("jsonwebtoken");

app.post("/api/login", async (req, res) => {
    const { email, password } = req.body;
    const user = await authenticateUser(email, password);
    if (!user) {
        return res.status(401).json({ error: "Invalid credentials" });
    }

    const verlyToken = jwt.sign(
        {
            user_id: user.id,
            email: user.email,
            name: user.name,
            custom_attributes: {
                plan: user.plan,
                company_id: user.companyId,
                support_tier: user.supportTier,
            },
            exp: Math.floor(Date.now() / 1000) + 60 * 60,
        },
        process.env.VERLY_SECRET,
        { algorithm: "HS256" }
    );

    res.json({
        user: { id: user.id, name: user.name },
        verlyToken: verlyToken,
    });
});
```

### 2. Frontend: Identify After Login

```javascript
async function onLoginSuccess() {
    const response = await fetch("/api/login", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ email, password }),
    });

    const { user, verlyToken } = await response.json();

    window.verly("identify", {
        token: verlyToken,
        name: user.name,
    });
}

function onLogout() {
    window.verly("resetUser");
    fetch("/api/logout", { method: "POST" });
}
```

### 3. Dashboard: Configure a Custom Action

In the Verly AI Dashboard, create a custom action with:

- **Name:** `get_user_orders`
- **Description:** "Fetch the user's recent orders"
- **Method:** GET
- **URL:** `https://api.yourapp.com/companies/{{contact.metadata.company_id}}/users/{{contact.externalId}}/orders`
- **Headers:** `X-Support-Tier: {{contact.metadata.support_tier}}`
- **Auth:** Bearer token (your API key)

When a verified user asks *"Show me my orders"*, the AI calls the action with all template variables auto-filled from the JWT — no code changes needed beyond the login integration above.
